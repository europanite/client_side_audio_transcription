# Full-body EMAGE -> VRM retargeting (experimental)

This patch replaces the old 8-joint `vrm1-emage-retarget-v2` approximations
with a 55-joint quaternion transport and a rest-pose/hierarchy retargeter.
The implementation takes inspiration from [VolgaGerm/emage-onnx-export](https://github.com/VolgaGerm/emage-onnx-export) (MIT): its SMPL-X parent table, VRM bone names, and world-to-local rest-frame concept. This repo **does not** download ONNX models or run inference in the browser. The existing offline PantoMatrix EMAGE GPU inference is unchanged.

## Pipeline

1. `emage-infer` writes 55-joint `poses` `[frames,165]` axis-angle NPZ.
2. `emage-convert` converts every axis-angle to a unit quaternion, packs them as
   little-endian float32/base64 in `emage-vrm-motion.json` (`smplx-vrm-retarget-v3`).
   Input `trans` is included as supplied (currently typically all zeros) but no
   fabricated global translation is applied.
3. `emage-apply` loads a VRM 1.0 model and computes the SMPL-X world hierarchy.
   It maps supported normalized VRM bones from their original unanimated rest
   frames, then solves for target local quaternions and slerps at playback time.
   No Euler axis permutation, motion clipping, gain, procedural arm-gesture
   overlay, or first-24-frame neutral-subtraction is performed.
4. Facial *expressions* (blink, smile, rough audio-level visemes) remain procedural;
   the generated SMPL-X face/hand *joint rotations* are preserved and mapped
   when VRM normalized bones support them. Unsupported joints are reported.

## Reuse the already generated EMAGE inference (no GPU)

Run at the repository root after applying the patch:

```bash
docker compose -f docker-compose.video.emage.yml build emage-convert emage-apply
docker compose -f docker-compose.video.emage.yml run --rm --no-deps emage-convert
docker compose -f docker-compose.video.emage.yml run --rm --no-deps emage-apply
```

`narration.wav` and `narrated-without-avatar.mp4` must exist in
`video/output/intermediate/` and must be the **same narration** used for the
existing `narration_output.npz`. A mismatched SHA-256 is rejected; in that case
rerun EMAGE inference with the new WAV. Note that the project export `.md`
contains only the **names** of binary output assets, not their bytes.

## Limitations and validation

- There is no guarantee of an anatomically faithful transfer from arbitrary
  SMPL-X skeletal rest frames to arbitrary VRM skeletons without additional
  joint-direction calibration or IK; this is a *baseline* for objective tests.
- Head/chest/arm/hand/leg rotations are transferred where normalized bones exist.
  Joints absent in the target VRM cannot be reproduced.
- EMAGE's current audio-only inference writes zero global translation, so
  translation is not synthesized or applied. The video crop might hide legs.
- Sound is never generated by retargeting; the compositor keeps using verified
  `narration.wav` as the AAC track.

Run converter and retargeter regression tests:

```bash
python3 -m unittest discover -s video/emage/tests -v
node --test video/avatar/smplx-retarget.test.mjs video/avatar/motion.test.mjs
```

Compare against source SMPL-X rendering, inspect left/right arms and fingers,
and quantify joint-direction and velocity discrepancies before claiming fidelity.
